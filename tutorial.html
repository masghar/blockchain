How ChainDemo Works

ChainDemo is a small, self-contained blockchain simulator. This page walks through the four ideas that make a blockchain a blockchain — hashing, chaining, proof-of-work, and tamper-evidence — and shows exactly where each one lives in this project's code.

1. What is a blockchain, really?

At its core, a blockchain is a list of records ("blocks") where each block stores a cryptographic fingerprint (a hash) of its own contents, and also stores the hash of the block before it. That second part is what turns a plain list into a chain: change anything in an earlier block, and its hash changes, which breaks the link the next block was pointing to.

2. Anatomy of a block

Every block in blockchain.js is an instance of the Block class:

class Block {
  constructor(index, timestamp, transactions, previousHash = '') {
    this.index = index;
    this.timestamp = timestamp;
    this.transactions = transactions;   // the data this block stores
    this.previousHash = previousHash;   // the link to the prior block
    this.nonce = 0;                     // explained in section 3
    this.hash = this.calculateHash();
  }
}

transactions is a plain array of { from, to, amount } objects — the "ledger entries" you create in the app's "Add Transaction" form.

3. Hashing and chaining

calculateHash() feeds every field of the block through SHA-256, a one-way function: the same input always produces the same 64-character hash, but you can't work backwards from a hash to guess the input, and changing even one character of the input produces a completely different hash. 

calculateHash() {
  return crypto.createHash('sha256').update(
    this.index + this.timestamp +
    JSON.stringify(this.transactions) +
    this.previousHash + this.nonce
  ).digest('hex');
}

Because previousHash is one of the ingredients, each block is cryptographically stitched to the one before it. That's the "chain" in blockchain.

4. Proof-of-work mining — done live, in your browser

Anyone could compute a valid-looking hash instantly, so blockchains add an artificial cost: a block's hash must start with a certain number of zero characters (the difficulty). There's no shortcut to find such a hash except to keep changing a throwaway number — the nonce — and re-hashing until you get lucky. That repeated search is "mining."

In this app, that search doesn't happen on the server — it happens for real, in your browser, inside a Web Worker (public/miner-worker.js), so the rest of the page stays responsive while it churns: 

while (!cancelled) {
  const hash = sha256Hex(buildMiningInput(index, timestamp, transactions, previousHash, nonce));
  attempts++;
  if (hash.startsWith(target)) {
    self.postMessage({ type: 'found', nonce, hash, attempts, elapsedMs });
    return;
  }
  nonce++;
}

The worker uses a small hand-written SHA-256 implementation (public/sha256.js) rather than the browser's built-in Web Crypto API — Web Crypto's subtle.digest() is asynchronous (one Promise per hash), which is far too slow for a tight search loop trying thousands of hashes a second. This hand-written version is tested against Node's own crypto module for a range of inputs, so it can never silently drift from what the server checks.

Since the browser is now the one doing the mining, the server can't just trust whatever hash it's told. So the flow is: POST /api/mine/start hands the browser a snapshot of what to mine against (the pending transactions, the previous hash, a fixed timestamp, and the difficulty); the browser searches for a nonce and shows you every step live; then POST /api/mine/submit sends back the nonce it found, and the server recomputes the hash itself before accepting the block. A client that lied about the nonce, or mined against stale pending transactions, gets rejected.

Try the difficulty slider in the app: each extra leading zero roughly multiplies the number of attempts needed by 16, so mining visibly takes longer — and you can watch it happen in the live mining console instead of just waiting.

5. Why tampering gets caught

The "tamper" control in the app lets you edit a mined transaction's amount directly — on purpose, without recomputing that block's hash, exactly like an attacker rewriting history would try to do. isChainValid() catches it by walking the chain from the start, checking each block against its own recalculated hash and against its neighbor's stored hash: 

isChainValid() {
  let brokenFrom = null;
  for (let i = 1; i < this.chain.length; i++) {
    const current = this.chain[i];
    const previous = this.chain[i - 1];
    const selfConsistent = current.hash === current.calculateHash();
    const linkedToPrevious = current.previousHash === previous.hash;
    if (!selfConsistent || !linkedToPrevious) {
      brokenFrom = i;
      break;
    }
  }
  const invalidBlocks = brokenFrom === null
    ? []
    : this.chain.slice(brokenFrom).map(block => block.index);
  return { valid: invalidBlocks.length === 0, invalidBlocks };
}

The tampered block fails immediately because its stored data no longer matches its stored hash. But notice what happens one block further downstream: that next block's own data never changed, so recalculating its hash still matches what's stored — the only thing that broke is the tampered block itself. If isChainValid() only compared each block to its immediate neighbor, the "invalid" flag would stop spreading right there, one hop past the tamper, even though everything after it now sits on top of a corrupted link.

That's why the loop stops at the first broken block and marks everything from that point to the end of the chain as invalid, rather than only flagging blocks whose direct link is broken. Once one block in the chain can't be trusted, nothing built on top of it can be trusted either — which is also why rewriting history in a real blockchain means re-mining every block after your edit, not just the one you changed.

6. Run it yourself

1. Install dependencies:

npm install

2. Start the server:

npm start

3. Open http://localhost:3000 in your browser.

4. (Optional) Run the unit tests for the core logic:

npm test

7. Using the GUI

  • Add Transaction — fill in from/to/amount and submit; it joins the pending pool waiting to be mined.
  • Difficulty slider — sets how many leading zeros the next mined block's hash must have (1–5).
  • ⛏ Start Mining — opens the live mining console: watch the nonce, the current hash attempt (color-coded against the target), attempts, elapsed time, and hashes/sec update in real time as your browser searches.
  • ✕ Cancel — stops an in-progress mining run immediately.
  • Tamper — edit any mined transaction's amount inline to see the chain turn invalid.
  • ✓ Validate Chain — walks the chain block-by-block, pulsing each one while it's checked, then shows exactly where (and everything after where) it breaks.
  • Stats bar — chain length, total transactions, current difficulty, and a live validity badge, always visible at the top of the page.
